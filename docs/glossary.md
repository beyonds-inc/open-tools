# open-tools ユビキタス言語辞書

文責：AI（松崎）

## 1. この文書の位置づけ

open-tools は静的 HTML の小ツール集で、同じ概念に対して「ツール／ユーティリティ／小ツール」のように複数の呼び名が混在している。文書・UI 文言・コミット・Issue で使う日本語を一つに寄せるための辞書で、用語の網羅は目的ではない。

### 1.1 スコープ

- **対象**: open-tools リポジトリ内の HTML / PHP / CSS / JS / 文書 / `.claude/skills/` 配下。
- **対象外**: 他リポジトリ。
- **対象外**: 全社共通の会社名・サービス名の表記ルール（`beyonds-brand` / `beyonds-master-data` が正）。

### 1.2 使い方

新しくツールページを作るとき・文書を書くときは「正式表記」の列を使う。「使わない別名」に載っている語は書かない。実装が辞書と食い違っていたら**実装が正**で、辞書側を直す（§5 に不整合として記録する）。

## 2. エントリの読み方

| 項目 | 意味 |
|------|------|
| 正式表記 | 文書・UI・コメントで使う日本語。これ以外を使わない |
| 使わない別名 | 実際に混在している表記。見つけたら正式表記に直す |
| コード上の識別子 | ファイル名・CSS クラス・ID・関数名。**リネーム対象ではない** |
| 定義 | 一行の定義。境界が曖昧な語は「〜ではない」を明示する |

## 3. サイト構造に関する用語

一覧ページ（`index.html`）と 21 個のツールページで構成される。カテゴリは 3 つ固定で、全ページ共通のヘッダー・フッターを持つ。

| 正式表記 | 使わない別名 | コード上の識別子 | 定義 |
|----------|--------------|------------------|------|
| ツール | ユーティリティ、小ツール、ツールページ | ルート直下の `<name>.html` / `.php`、`section#tool` | 1 ファイル = 1 ツール。ビルド工程なしでブラウザから直接開ける単体ページ。現在 21 個 |
| 一覧ページ | トップページ、ホーム、ツール一覧ページ | `index.html` | 全ツールをカードで並べる入口。フッターの「一覧へ戻る」の遷移先 |
| カード | エントリ、タイル | `article.card`, `.card-grid`, 一覧ページの `<h3>` | 一覧ページに置く 1 ツール分の見出し＋説明＋リンク。ツール本体とは別に名前を持つため、ここがツール名のブレの発生源になる（§5-2） |
| カテゴリ | セクション、ジャンル、分類 | `#util` / `#dev` / `#web` | ツールの分類。**3 つ固定**で、増やす場合は一覧ページ・全ツールの nav・雛形の 3 か所を同時に直す必要がある |
| 便利ツール | — | `#util` | 日付計算・文字種変換など、日常で使う小ツール |
| プログラミング向け | プログラミング | `#dev` | ソース整形・データ変換など、開発補助のツール。nav ラベルだけ「向け」が無い（§5-3） |
| ウェブ制作向け | ウェブ制作 | `#web` | タグ変換・文字数チェックなど、コンテンツ制作を助けるツール。nav ラベルだけ「向け」が無い（§5-3） |
| サイトヘッダー | ヘッダ、ヘッダー | `header.site-header`, `.site-nav`, `.brand` | 全ページ共通の上部ナビ。**C 言語のヘッダファイル（`header.html` が生成する対象）とは別物**（§5-6） |
| サイトフッター | フッター | `footer#site-footer`, `js/footer.js` | `js/footer.js` が実行時に描画する共通フッター。HTML 側には空の `<footer id="site-footer">` だけを置く |

## 4. ツールページ内部の用語

| 正式表記 | 使わない別名 | コード上の識別子 | 定義 |
|----------|--------------|------------------|------|
| 雛形 | テンプレート、boilerplate、ボイラープレート | `.claude/skills/tool-creator/assets/boilerplate.html` | 新規ツールの元にする HTML。**ルート直下には存在しない**（§5-4） |
| ツールパネル | 入出力エリア、フォーム | `.tool-panel`, `.stack`, `.inline-controls` | ツールの入力・操作・出力をまとめる箱。ページ内のツール本体はここに収める |
| 実行ボタン | 変換ボタン、処理ボタン | `.btn.btn-primary` | 主操作のボタン。ラベルはツール固有の動詞（変換 / 計算 / 生成 / 抽出）にする。「実行」は雛形のプレースホルダで実ページでは使わない（§5-7） |
| リセットボタン | クリアボタン | `.btn.btn-ghost`, `resetFields()` | 入出力を空に戻す副操作。ラベルは「リセット」に寄せる（§5-7） |
| デザイントークン | CSS 変数、テーマ変数、カラー変数 | `main.css` の `:root`（`--color-primary`, `--radius`, `--shadow-soft` 等） | 色・角丸・影の定義。ページ内 `<style>` で色を直書きしない |
| ブラウザ完結 | ローカル処理、クライアントサイド | （実装上の識別子なし） | 入力をサーバーへ送らず、ページ内 JS だけで処理すること。本リポジトリの基本方針。`tostr.php` は例外（§5-8） |

## 6. 用語を追加・変更する手順

辞書が実装から遅れると誰も見なくなる。追加・変更は軽い手順で回す。

1. 追加は実装と同じ PR に含める。単独 PR にしない。
2. 実装とズレていたら、**コード側を直せるなら直す**。直せないなら §5 に不整合として書く。
3. 「使わない別名」に語を追加しても、既存の混在を一括置換しない。触ったファイルだけ直す。
4. ツールを新規追加するときは `<title>` / `<h1>` / 一覧ページのカード `<h3>` の 3 か所を同じツール名で揃える（§5-1, §5-2 を増やさない）。
